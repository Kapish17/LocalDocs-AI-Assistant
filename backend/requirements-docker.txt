# Slim, CPU-only dependency set for the production/Docker backend image.
# Built from actually reading every import under backend/{api,core,rag,llm,loaders,utils} —
# not a copy of backend/requirements.txt. Keep backend/requirements.txt itself
# unchanged; it stays the source of truth for local dev.
#
# Deliberately excluded (present in requirements.txt, not needed here):
#   docx2txt      - not imported anywhere in backend/; DOCX parsing actually
#                    uses `import docx` (python-docx) in loaders/docx_loader.py.
#   beautifulsoup4 - not imported anywhere in backend/.
#   sentence-transformers, transformers, langchain-huggingface
#                  - only needed by rag/embeddings.py's "local" embedding
#                    provider (EMBEDDING_PROVIDER=local), an explicit
#                    opt-in for local development. This image runs with
#                    EMBEDDING_PROVIDER=remote (the default): embeddings
#                    are generated by calling Hugging Face Inference
#                    Providers' hosted feature-extraction API instead of
#                    loading a model locally — see rag/embeddings.py and
#                    README "Embeddings" for why (Render Free's 512 MB
#                    memory limit). huggingface_hub (below) is all that's
#                    needed to call that API.
#
# torch and torchvision are installed separately, PINNED to an exact
# matching pair (torch==2.14.0 / torchvision==0.29.0), from the CPU-only
# PyTorch wheel index, in backend/Dockerfile *before* this file is
# installed - see the Dockerfile comment. Do not add "torch" or
# "torchvision" lines here: letting pip pull torchvision in transitively
# at this step (it's a dependency of easyocr, below) resolves it from the
# default PyPI index instead of the CPU index, which caused
# "RuntimeError: operator torchvision::nms does not exist" at startup
# (matching version number, mismatched build/ABI). If you ever bump the
# pinned pair in the Dockerfile, keep torch==torchvision's declared
# requirement (check torchvision's PyPI metadata for the exact torch
# version it requires) and bump both together. torch itself is still
# needed here — by easyocr (OCR), not by embeddings anymore.
